# 商业版本发布门禁

## 原则

“页面可操作”“模型返回成功”或“一次实模通过”都不是商业发布证明。商业候选必须同时证明构建、数据、安全、生成、媒体、费用、恢复和运营链路。

机器可读的当前候选状态位于 `docs/release/evidence/commercial-candidate.json`。CI 的 `commercial-release-gate` 对 `dev` 和 `releases` 校验清单结构并允许保留明确阻塞项；目标为 `main` 的 PR 必须来自 `releases`，且 G0-G8 全部通过、证据存在并仍在有效期内。校验失败时必须按输出的中文修复动作补齐证据，不得删除门禁或把阻塞项改成无证据的通过。

## G0：仓库与变更

- 目标提交来自受保护的 `releases`。
- 工作区干净，没有生成物、凭据和临时数据库。
- PR 已说明 API、数据、供应商、成本、权限、UX 和回滚影响。
- CODEOWNERS 和必需检查已通过。

## G1：构建与依赖

- 前端 typecheck 和 production build 通过。
- 后端在 SQLite 与 PostgreSQL 上通过契约测试。
- 生产 Docker 镜像可重复构建并记录摘要。
- 严重和高危依赖漏洞为零；例外必须有责任人、缓解措施和到期时间。
- 许可证清单与产品版权声明一致。

## G2：配置与安全

- 生产启动拒绝默认 JWT 密钥、开发模式和弱基础设施密码。
- 密钥来自受控 Secret Manager，不写入仓库、日志或前端。
- CORS、Cookie、安全响应头、限流和异常脱敏通过测试。
- 用户、组织、项目和管理员权限矩阵通过正向与越权测试。
- 关键配置、发布、模型绑定、额度和人工操作写入审计日志。

## G3：数据库与恢复

- 所有迁移使用同一有序工具执行，支持升级前检查。
- staging 使用生产同类数据库完成升级与回滚演练。
- 数据库和对象存储备份可恢复，记录实际 RPO/RTO。
- 回填脚本幂等，可试运行，并输出处理数量和失败明细。

## G4：任务与媒体

- 创建、排队、执行、轮询、失败、重试、取消和重启恢复均有持久状态。
- 幂等键能阻止重复生成和重复计费。
- 供应商任务与本地任务可重新对账。
- 媒体写入私有对象存储，可通过签名 URL 播放并按策略过期。
- 字幕、音频、视频、封面和最终合成物均可追溯到输入和模型绑定。

## G5：实模与参考资产

- 实模任务记录模型、供应商账号、提示词版本、参考图角色、顺序、裁剪和模型输入限制。
- 角色、场景、道具参考图实际进入供应商请求，而不是只显示在页面。
- 多章节人物和资产一致性通过人工及机器验收。
- 失败提示使用中文直白说明，并包含可执行修复动作。
- 真实消费有单次预算、总预算和停止条件。

## G6：费用与结算

- 提交前展示预计费用、积分和可能变化范围。
- 请求、预扣、供应商消费、最终扣减、退款和余额形成不可变流水。
- 失败、超时、取消和重复回调不会重复扣费。
- 供应商账单、内部成本和用户账单可按任务 ID 对账。
- 财务差异超过阈值时自动阻断发布或结算。

## G7：产品 UAT

- 注册、验证、登录、退出、找回和重置密码通过。
- 创建小说、章节、实体、剧本、分镜、资产、视频、字幕、合成和导出通过。
- 中途关闭页面、服务重启和供应商延迟后可以恢复。
- 正式环境不出现 E2E 小说、测试角色、验收模型和临时媒体。
- 桌面与移动端完成无障碍、响应式和关键视觉回归。

## G8：运维与发布

- liveness、readiness、数据库、队列、对象存储和供应商依赖监控可见。
- 告警有负责人、处理手册和升级路径。
- 发布前完成数据库备份和当前镜像保留。
- canary 指标正常后再扩大流量。
- 回滚演练覆盖应用、迁移、队列任务和前端静态资源。

## 发布结论

- 任一 P0 门禁失败：`No-Go`。
- 只有受控文本能力通过：只能标记受限试用，不得宣称整个平台商用。
- 所有 G0-G8 证据齐全：可以进入商业候选，不等于自动正式发布。
- `commercial-release-gate` 通过只表示证明清单满足机器合同；正式发布仍需要 CODEOWNERS 审核和发布负责人确认。
