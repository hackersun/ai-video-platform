# 商用就绪路线图

当前代码证据、风险等级、登录页规格和逐批迁移/回滚办法见[商用差距分析与平滑改造计划](commercial-gap-analysis.md)。本文件只保留阶段目标；两者冲突时，以商业发布门禁和经审批的单批执行合同为准。

## 目标

通过小步、可回滚的垂直批次，把现有实模制作平台提升为可以稳定交付、计费、审计和支持客户的商业系统。任何阶段都不通过一次性重写换取表面整洁。

## P0：商业候选前必须完成

### 1. 仓库与发布基础

- 完成代码健康棘轮、目录地图和三线分支。
- 修复 PostgreSQL CI 和生产镜像构建。
- 固定后端依赖，升级严重和高危前端依赖。
- 建立制品、迁移、版本、发布说明和回滚记录。

### 2. 身份、权限和安全

- 生产配置 fail-closed。
- 完成安全 Cookie、Refresh Token 轮换和会话撤销。
- 建立组织、工作区、项目 RBAC 和 API 权限矩阵。
- 邮箱验证、密码强度、限流、审计日志和异常脱敏上线。

### 3. 数据、任务和媒体

- Alembic 成为唯一迁移通道。
- 持久任务队列、幂等、重试、死信和重启恢复上线。
- 对象存储私有化、签名播放、生命周期和删除策略上线。
- 数据库与媒体备份恢复通过演练。

### 4. 用量与费用闭环

- 提交前费用预估和用户确认。
- 不可变用量流水、预扣、结算、退款和余额。
- 供应商消费与内部流水对账。
- 客户预算和运营实模测试预算分离，测试旁路不能影响生产租户安全控制。

## P1：正式商业体验

### 登录与注册

- 复用当前登录页的清晰分栏方向，抽取统一 AuthShell。
- 注册、找回和重置密码迁移到同一视觉系统。
- 增加隐私、条款、邮箱验证、企业登录和支持入口。

### 首页

- 增加真实案例、生成流程、支持模型和产物示例。
- 说明价格、服务边界、版权、安全、SLA 和客服方式。
- 统一品牌颜色、字体、按钮和版权年份。

### 仪表盘

- 只保留一个“继续制作”主操作。
- 统计、最近项目和生产状态使用同一后端真相源。
- 测试数据和真实租户数据物理或逻辑隔离。
- 空封面、失败媒体和等待任务显示直白中文状态与修复动作。

### 快速开始

- “体验演示”允许使用故事设定快速生成样例。
- “商业制作”必须提供真实章节正文，不得用 premise 冒充章节内容。
- 提交前展示模型、提示词版本、参考资产、预计时间和预计费用。
- 草稿、任务和恢复点保存到服务端。

### 生产一致性

- 角色、场景、道具参考图根据模型输入数量和角色限制自动选择。
- 记录实际进入视频模型的图片、顺序、角色和裁剪方式。
- 跨章人物视觉 DNA、服装、声线、字幕和镜头资产通过可复现验收。

## P2：运营规模化

- 套餐、席位、额度、项目预算和企业合同。
- 运营、财务、客服、审核和安全后台。
- 监控、告警、值班、事故响应和客户 SLA。
- 数据导出删除、版权申诉、内容安全和合规留存。
- 灰度发布、容量测试、成本预测和供应商故障切换。

## 执行批次

每个主题必须形成独立设计和提交序列：

1. PostgreSQL/Alembic 与生产容器。
2. 会话安全与组织 RBAC。
3. 持久任务队列与供应商对账。
4. 对象存储与媒体交付。
5. AuthShell、首页和注册流程。
6. 仪表盘数据真相与 Quick Start 商业模式。
7. 用量流水、额度、结算和退款。

每个批次都要给出 intent lock、兼容边界、数据迁移、回滚、目标测试和运行态截图或日志证据。

## 商用完成定义

商业就绪以 [商业版本发布门禁](../release/commercial-release-gates.md) 为唯一验收入口。计划完成、页面可见、单模型通过或本地构建成功都不能单独改变发布结论。
