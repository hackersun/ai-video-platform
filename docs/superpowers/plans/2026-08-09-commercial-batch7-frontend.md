# 商用前端入口与安全升级 Implementation Plan

**Goal:** 将首页与登录入口调整为可理解、可返回原任务、响应式稳定的商用入口，并消除当前前端依赖高危漏洞。

## Execution Contract

**Intent Lock:** 用户在首页能理解产品、明确开始或登录，认证后回到原目标；前端运行在仍受安全维护的 Next.js 版本。

**Out of Scope:** 不重写工作台业务页、不改认证 API、不引入新设计系统、不更换品牌色、不采用 Next.js 预览版或 Canary。

**Constraints:**

- 沿用现有深色、紫色主品牌与 Lucide 图标，不新增伪造素材。
- 首页静态内容由服务端组件输出，仅认证相关按钮保留最小客户端岛。
- 登录错误保持中文直白描述，密码不写入 URL、日志或持久存储。
- `next` 升级到 16.3 稳定安全线，React 与类型同步到 19；逐项处理破坏性 API。
- 桌面与 390px 移动端不得横向溢出，键盘焦点和表单标签保持可用。

**Acceptance Criteria:**

1. 未登录首页主按钮进入登录页；已登录进入快速向导。
2. 首页有品牌导航、登录/工作台入口、清晰主次按钮和当前年份页脚。
3. 登录页支持显示/隐藏密码；带安全 `next` 参数时登录成功返回原任务，外部 URL 被拒绝。
4. 首页不再整体声明为客户端组件，认证状态仅由小型组件处理。
5. Next.js 16.3.0 + React 19 构建通过，`npm audit` 无高危或严重漏洞。
6. 目标 Playwright、全量 typecheck/build、核心页面响应式截图和控制台检查通过。
