# 商用私有媒体与数据生命周期 Implementation Plan

**Goal:** 客户媒体默认私有，播放和供应商引用都通过短时授权出口，媒体保留、删除和实际供应商输入可审计。

**Architecture:** 新增以用户和项目为边界的媒体对象登记表，数据库只保存稳定对象标识和存储键，不保存短时签名。播放 API 在每次授权后生成新签名；供应商引用继续复用现有媒体交付门面，并只记录脱敏输入清单。生产环境不挂载本地 `/static`，本地文件仅保留 local/test 兼容。

**Tech Stack:** FastAPI、async SQLAlchemy、Alembic、PostgreSQL/SQLite、现有七牛对象存储适配器、pytest。

## Execution Contract

**Intent Lock:** 客户原文和媒体不能被匿名或其他客户读取，同时仍可可靠交给已授权播放器和模型供应商。

**Out of Scope:** 本批不重写全部历史媒体生成器、不增加新的对象存储供应商、不立即删除历史本地文件、不改变现有生成端点路径。

**Constraints:**

- 生产环境禁止公开挂载 `/static`，也不挂载用户媒体持久卷。
- 数据库不得持久化带 token 的签名 URL；签名必须短时生成并可刷新。
- 媒体对象必须包含用户、项目、类别、稳定存储键、哈希、保留期和法律保留状态。
- 跨用户访问统一返回不存在，避免泄漏对象是否存在。
- 供应商输入清单记录对象、顺序、用途、模型任务和有效期，不记录签名 token。
- 删除申请幂等；法律保留阻止删除；删除回执只追加不可修改。
- 迁移采用复制、哈希校验、切换引用、观察后清理，不主动删除现有文件。

**Acceptance Criteria:**

1. production/staging 不注册 `/static` 路由；local/test 保持已有预览兼容。
2. 当前用户可获取短时播放地址，其他用户得到 404；刷新产生新的有效期。
3. 私有对象被发送给供应商时记录脱敏输入清单，签名参数不会进入数据库或日志证据。
4. 原始、过程和最终媒体拥有不同默认保留期和对象前缀。
5. 删除申请可重试，法律保留时拒绝执行，成功或对象缺失均形成不可变回执。
6. 数据迁移脚本支持 dry-run、复制后哈希校验和幂等重跑，不删除源文件。
7. SQLite、PostgreSQL、全量后端、前端、代码健康、Compose 和 Docker 门禁通过。
