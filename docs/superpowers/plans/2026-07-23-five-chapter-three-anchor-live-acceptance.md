# 五章 3D 玄幻修仙实模验收实施计划

## Intent Lock

让用户可以从前端新建任意连续章节的小说，并以“前、中、后 3 个代表镜头”模式完成资产、剧本、分镜、镜头、视频、原生语音和字幕的可恢复实模生产；本次以全新 5 章 3D 玄幻修仙小说完成验收。

## Assumptions

- 沿用 sunqy 当前持久化的文本、Seedream 图像和 Seedance 视频模型配置，不在代码中写入密钥或模型标识。
- 视频使用 Seedance 原生语音，不额外调用 TTS；字幕仍需由平台对白谱系和原生音轨渲染链闭环生成。
- 三个代表镜头覆盖首章、中间章和末章；每章选择一致性与对白信息较完整的最高分镜头。
- 保留当前开发数据库和未提交工作，不重置、不覆盖已有用户数据。
- 实模付费范围限定为 3 个视频；失败仅允许从前端对失败步骤单项修复或重试。

## Scope

### In scope

- 新增 `representative` 三镜头模式，并由同一份后端契约维护目标镜头数与章节覆盖数。
- 去除整书工作台对“必须恰好 4 章”的限制，支持 5 章连续章节。
- 前端提供清晰的三镜头入口、失败原因、修改后重试、单项重试和返回工作台路径。
- 从前端新建 5 章小说并依次完成实模生产。
- 对 3 个视频验证 3D 风格、角色性别/服装、场景/道具、对白/原生语音、字幕及跨章一致性。

### Out of scope

- 不重构现有整书编排架构。
- 不改变现有 `smoke` 两镜头和 `full` 六镜头模式语义。
- 不清理或迁移已有小说、资产、模型配置与历史任务。
- 不绕过前端直接写 API 来制造验收数据。

## Acceptance Criteria

1. 5 个连续章节可在小说前端启动整书自动制作。
2. 前端可选择“3 个代表镜头”，后端稳定返回首/中/末三章各一个镜头。
3. 预检、预算和生成接口对三镜头模式采用同一契约，不再出现 2/6 镜头硬编码冲突。
4. 全部生产写操作由前端表单或按钮触发；API/数据库只用于只读取证。
5. 失败卡片展示可读原因与可执行恢复动作，且可以只重试失败项。
6. 三个视频均有可播放公网地址、视频流和音频流；有对白的镜头必须有字幕轨或明确阻断原因。
7. 人物性别、脸部、发型、固定服装和核心道具在三章代表镜头中无明显漂移；否则不得宣称通过。
8. 新增/受影响的后端测试、前端类型检查和构建通过，浏览器前端验收有可追溯证据。

## Implementation Steps

### 1. 先建立失败测试

- 在锚点镜头服务测试中加入 5 章 `representative` 选择与覆盖断言。
- 在实模预检测试中加入三镜头目标数和三章节覆盖断言。
- 在前端测试中加入 5 章可启动、三镜头按钮可选择及恢复文案断言。

### 2. 后端契约与预检

- 在锚点镜头领域服务中集中定义模式契约。
- 扩展请求 schema 和系列运行 API 支持 `representative`。
- 预检复用领域契约计算目标数量和覆盖章节，保留现有预算安全门。

### 3. 前端动态章节与三镜头模式

- 共享前端锚点模式类型和展示文案。
- 允许不少于 2 章的连续章节启动整书制作，并动态展示章节数。
- 提供三镜头模式与清晰的失败项单独重试入口。

### 4. 确定性验证

- 运行锚点服务、预检和系列运行相关后端测试。
- 运行前端相关 Playwright 测试、TypeScript 检查和生产构建。
- 启动前后端，确认 `/health` 与工作台页面可访问。

### 5. 前端实模生产

- 使用 sunqy 身份从小说前端新建全新 5 章 3D 玄幻修仙小说。
- 从前端完成章节保存、整书启动、故事锁、实体/资产、剧本/分镜和三代表镜头选择。
- 从前端生成并锁定参考资产，再从前端生成三个镜头首帧与 Seedance 原生语音视频。
- 如遇失败，只使用页面提供的修复、修改后重试或单项重试。

### 6. 成片验收

- 用只读 API 记录小说、章节、运行、镜头、任务和媒体标识。
- 用 `ffprobe` 验证三条视频的时长、视频流和音频流；检查字幕文件/轨道与对白谱系。
- 抽取首中尾帧人工检查 3D 风格、人物性别、脸部、发型、固定服装、场景和道具。
- 输出通过/不通过矩阵；不满足的项给出前端可执行修复入口并继续闭环。

## Decision Points

- 若前端预检显示预计费用超过现有人民币 10 元安全门，停止付费调用并保留已完成的免费步骤。
- 若模型认证失效，先从模型中心前端测试/修复连接，不以脚本写入密钥或绕过认证。
- 若同一付费镜头单项重试后仍失败，停止该镜头继续扣费，交付明确原因与前端人工处理路径。
