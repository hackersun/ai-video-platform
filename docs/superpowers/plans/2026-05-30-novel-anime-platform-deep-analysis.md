# 小说动画漫剧平台 - 深入需求分析与优化方案

> **日期**: 2026-05-30
> **目标**: 实现生产级小说到动画漫剧的全流程AI辅助生产平台

---

## 一、需求与背景

### 1.1 核心目标

用户能够通过**小说导入或编辑**，完成整部小说的**动画漫剧**制作。平台需要：

1. **一致性保持**：剧情、人物、环境、事件、道具、配音、形象在整个制作流程中保持一致性和连续性
2. **AI全面辅助**：全流程各环节都利用AI辅助能力，降低使用门槛
3. **操作简单化**：界面操作尽量简单，每个操作流程都有AI能力辅助
4. **生产级能力**：具备实际生产应用的能力，包括配置权限和菜单功能
5. **数据安全**：确保改动后功能可用，现有数据不丢失

### 1.2 目标用户

- **内容创作者**：小说作者、编剧、自媒体
- **制作团队**：动画工作室、视频制作团队
- **教育场景**：影视制作教学、创意写作课程

## 三、关键差距分析

### 3.1 P0 阻断性问题

#### 1. 小说导入缺失
- **现状**：只能手动创建小说或AI生成
- **缺口**：无TXT/MD/DOCX/EPUB/PDF导入、章节切分确认、导入预览
- **影响**：用户无法快速导入现有小说作品

#### 2. 权限未完全隔离
- **现状**：大多数API只按`user_id`校验
- **缺口**：ProjectMember角色（owner/editor/viewer）未执行到资源访问
- **影响**：团队协作存在安全隐患

#### 3. 真实合成缺失
- **现状**：非DEV_MODE下合成只是pending占位
- **缺口**：无FFmpeg执行、多镜头拼接、字幕烧录、音频混音
- **影响**：无法产出真实可发布的最终作品

#### 4. 实体系统不完整
- **现状**：只支持角色抽取
- **缺口**：无场景、道具、事件的完整抽取和版本管理
- **影响**：Story Bible依赖手工维护

### 3.2 P1 体验问题

#### 5. 批量生成不完善
- **缺口**：批量镜头生成、失败重试、质量验收
- **需求**：一键生成本集全部镜头

#### 6. Timeline编辑器
- **缺口**：无可视化轨道、字幕轨、音效轨、BGM轨
- **需求**：可视化编辑最终成片

#### 7. 版本管理
- **缺口**：Novel/Chapter/Script/Storyboard/Shot无版本历史
- **需求**：草稿版本和回滚能力

### 3.3 P2 增强功能

#### 8. 成本预算
- **缺口**：无token/图片/视频/TTS成本估算
- **需求**：生成前提示成本

#### 9. 模板市场
- **缺口**：无公共资产和模板库
- **需求**：素材市场和提示词模板

## 四、优化方案

### 4.1 第一阶段：核心功能闭环（P0）

#### A. 小说导入管线

**目标**：支持一键导入外部小说，自动切分章节

**技术方案**：
1. 新增`ImportJob`模型：文件名、格式、状态、解析统计
2. 支持格式优先级：TXT/Markdown（优先）→ DOCX/EPUB/PDF（后续）
3. 后端接口：上传、预览、确认导入、失败重试
4. AI辅助章节识别：LLM分析文本结构，自动切分章节

**实现要点**：
- 导入向导：上传 → 编码检测 → 章节识别预览 → 确认创建
- 章节可合并/拆分/重命名
- 支持撤销重导

#### B. 统一实体抽取与审阅

**目标**：从小说中自动抽取角色、场景、道具、事件

**技术方案**：
1. 扩展`StoryEntity`模型：支持entity_type（character/scene/prop/event）
2. 统一JSON schema：
   ```json
   {
     "canonical_name": "xxx",
     "aliases": ["别名1", "别名2"],
     "type": "character|scene|prop|event",
     "description": "描述",
     "first_seen": "chapter_id",
     "mentions": ["chapter_id列表"],
     "state_changes": [],
     "relations": []
   }
   ```
3. 前端实体审阅台：合并重复、确认归属、编辑描述

#### C. Story Bible自动构建

**目标**：从小说自动生成Story Bible，保持与章节同步

**技术方案**：
1. `/story-bibles/generate-from-novel`：从小说全部章节生成
2. `/story-bibles/sync-from-chapter`：章节编辑后增量同步
3. `/story-bibles/check-consistency`：一致性检查，冲突检测
4. 冲突类型：人物外观冲突、道具状态冲突、事件顺序冲突

**实现要点**：
- 章节编辑后标记Story Bible stale
- 严重冲突阻断一键生成
- 记录所有冲突供人工确认

#### D. 参考资产生成和版本锁定

**目标**：角色、场景、道具生成定稿图，版本锁定

**技术方案**：
1. Asset增加字段：`entity_type`, `entity_id`, `version`, `is_locked`, `source_job_id`
2. Shot生成时锁定asset version
3. 定稿图变化不影响已生成镜头（除非用户明确重新绑定）

**实现要点**：
- 角色定稿图：头像、全身、表情、姿态
- 场景定稿图：地点、固定构图、时代/材质/光照
- 道具定稿图：外观、归属、状态

#### E. 一键生产链路

**目标**：Chapter → Script → Storyboard → Shot 全自动

**技术方案**：
1. 剧本生成支持`chapter_id`/`novel_id`，带Story Bible上下文
2. 分镜生成支持`chapter_id`/`script_id`两种入口
3. 落库完整保存：camera_movement、sfx_cue、music_cue、scene_refs、prop_refs、event_refs

**实现要点**：
- 从章节页点击"生成分镜"可一键创建剧本+分镜+镜头
- 保留可编辑中间产物
- 生成失败支持断点重试

#### F. 权限隔离

**目标**：ProjectMember角色执行到资源访问级别

**技术方案**：
1. 抽出`require_project_role(project_id, min_role)`装饰器
2. 给Novel/Chapter/Character/Script/Storyboard/Shot/Asset/Job补`project_id`
3. ProjectMember支持邀请、角色变更、移除
4. 前端团队页改为真实接口

**权限矩阵**：
| 角色 | 查看 | 编辑 | 生成 | 删除 | 管理 |
|------|------|------|------|------|------|
| viewer | ✓ | ✗ | ✗ | ✗ | ✗ |
| editor | ✓ | ✓ | ✓ | ✗ | ✗ |
| owner | ✓ | ✓ | ✓ | ✓ | ✓ |

#### G. 真实合成与发布

**目标**：产出真实可下载/可发布的最终作品

**技术方案**：
1. 接入本地FFmpeg：多镜头拼接、音频混合、字幕烧录/外挂
2. 新增`FinalVideo`/`Publication`模型：文件路径、封面、标题、状态
3. 支持导出格式：MP4、MOV、WebM
4. 支持横屏/竖屏、封面比例

**实现要点**：
- 本地执行合成，非DEV_MODE也真实产出
- 支持字幕轨、音效轨、BGM轨混音
- 封面帧自动抽取

## 六、关键实现细节

### 6.1 AI辅助流程

每个操作环节都嵌入AI辅助：

```
导入阶段：
  文件上传 → AI章节识别 → 预览确认

实体抽取：
  全局分析 → 实体识别 → 关系抽取 → 审阅台确认

Story Bible：
  自动构建 → 冲突检测 → 人工确认 → 版本锁定

生产链路：
  Chapter → AI剧本生成 → AI分镜生成 → AI镜头细化 → 人工审阅

视频生成：
  Prompt自动补全 → 资产自动注入 → 生成 → 质量检查

合成导出：
  自动拼接顺序 → AI字幕生成 → 混音调整 → 导出
```

### 6.2 数据迁移策略

确保现有数据不丢失：

1. **向后兼容**：新增字段提供默认值，不破坏现有数据
2. **渐进式迁移**：逐个模块迁移，不一次性全量改动
3. **数据备份**：每次关键改动前备份数据库
4. **版本记录**：模型变更记录版本号，支持回滚

### 6.3 一致性保证机制

```
生成请求 → PromptComposer
           ├── 项目风格
           ├── Story Bible规则
           ├── 角色状态机
           ├── 场景状态机
           ├── 道具状态机
           └── 当前事件上下文

输出约束：
  - 人物外观一致性
  - 场景环境一致性
  - 道具状态连续性
  - 事件时间线连续性
```

## 九、总结

本方案通过三个阶段的实施，使平台具备：

1. **生产级能力**：从小说导入到最终作品发布的完整链路
2. **AI全面辅助**：每个操作环节都有AI能力加持
3. **操作简单化**：复杂任务简化为3步操作
4. **一致性保证**：通过Story Bible状态机和资产版本锁定确保质量
5. **数据安全**：渐进式迁移，数据不丢失

**核心价值**：
- 降低创作门槛，让非专业用户也能制作动画漫剧
- 提升生产效率，AI辅助减少人工干预
- 保证内容质量，一致性机制确保作品质量稳定
