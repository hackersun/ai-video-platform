# 提示词使用地图重设计

日期：2026-08-07
状态：已完成交互设计确认，等待实施计划
目标页面：模型中心 / 提示词模板

## 1. 背景与问题

现有页面以“模板、版本、结构化字段”为主线。它适合底层配置维护，却无法快速回答生产人员最关心的问题：

> 小说续写、实体提取、剧本、分镜、参考图、视频和配音等生产环节，当前实际使用的是哪个提示词模板？

当前运行时提示词选择还会受到任务、阶段、供应商、模型、模型能力和输出契约影响。模板详情、模型绑定、生产方案和旧版 Prompt Skill 分散展示，导致页面上的“已发布模板”不等于“当前任务实际会使用的模板”。

## 2. 意图锁

把提示词模板默认页面重构为“生产环节提示词使用地图”，让用户在 5 秒内看清每个生产环节的最终生效模板、版本、模型、绑定来源和异常状态，同时保留现有版本治理能力。

## 3. 范围

### 3.1 包含

- 新的默认“提示词使用地图”。
- 完整生产链环节及其真实 Prompt task 映射。
- 基于 canonical prompt router 的批量只读生效解析。
- 系统当前默认模型下的真实生效结果，以及单环节指定模型预览。
- 环节详情、模板正文、创建草稿、预览和发布入口。
- 原模板版本工作台迁移为二级“模板库”。
- 中文、可操作的异常状态和发布影响说明。

### 3.2 不包含

- 不删除、合并或迁移现有提示词模板和版本数据。
- 不改变 canonical prompt router 的优先级和生产行为。
- 不让前端复制后端路由规则。
- 不把字幕、合成等当前不使用 Prompt 路由的环节伪装成已绑定。
- 不在本次重设计中重做模型目录、供应商连接或生产方案页面。

## 4. 方案比较与选择

比较了三个方向：

1. **生产流程地图**：按生产顺序展示环节，右侧查看实际生效详情。
2. **环节卡片看板**：所有环节平铺，状态醒目，但环节增多后页面过长。
3. **模板资产表**：在模板列表中显示使用环节，适合运维治理，但仍需反向推导实际生效关系。

最终选择方案 1。它直接对应用户的核心问题，且能把复杂版本字段收进二级详情。

## 5. 信息架构

### 5.1 顶部概览

显示：

- 生产环节总数
- 已配置数量
- 存在覆盖数量
- 未绑定或回退数量
- “只看问题环节”开关
- 当前配置标签：系统当前默认配置

### 5.2 左侧生产流程

按四组展示：

1. **故事开发**：小说续写、角色提取、场景/道具提取
2. **内容制作**：剧本生成、分镜生成
3. **视觉生产**：角色参考图、场景参考图、道具参考图、镜头视频
4. **声音与交付**：配音、字幕、合成

每个环节默认只展示：

- 环节名称
- 当前模板名称与版本
- 当前使用模型
- 生效状态

### 5.3 右侧环节详情

默认详情显示：

- 最终生效模板正文
- 模板名称、版本、版本 ID、发布时间
- 实际使用模型
- 命中规则和绑定来源
- 当前命中的模型、供应商或能力范围
- 是否回退到代码内置提示词

主要操作：

- 更换模板
- 编辑正文并创建新草稿
- 预览效果
- 发布并用于当前模型

### 5.4 高级设置

以下内容默认折叠：

- 系统约束
- 输入变量映射
- 输出结构
- 负向约束
- 模型系列覆盖
- 版本历史、差异和回滚
- 旧版 Prompt Skill 兼容信息

### 5.5 模板库

原模板版本工作台保留为二级入口“模板库”，用于批量搜索、版本治理、清理和旧版兼容操作，不再作为默认首页。

## 6. 生产环节注册表

使用一个后端拥有的声明式环节注册表，记录展示名称、分组、任务键、阶段、能力和是否使用 Prompt 路由。

| 展示环节 | Prompt task | 说明 |
|---|---|---|
| 小说续写 | `chapter_writing` | 章节续写和下一章生成 |
| 角色提取 | `entity_extraction` | 使用实体提取路由，界面按角色用途解释 |
| 场景/道具提取 | `entity_extraction` | 与角色共享任务模板，明确显示共享关系 |
| 剧本生成 | `script_generation` | 章节到剧本 |
| 分镜生成 | `storyboard_generation` | 剧本到结构化分镜 |
| 角色参考图 | `character_image` | 角色设定和三视图 |
| 场景参考图 | `scene_reference_image` | 场景参考图 |
| 道具参考图 | `prop_image` | 道具设定图 |
| 镜头视频 | `shot_video` | 镜头级视频提示词 |
| 配音 | `tts_dialogue` | 台词和声音生成 |
| 字幕 | 不适用 | 当前不经过 Prompt router |
| 合成 | 不适用 | 当前不经过 Prompt router |

注册表不得在前后端各维护一份。后端返回展示所需的稳定标识、名称和顺序，前端只负责呈现。

## 7. 实际生效解析

### 7.1 单一规则所有者

新增批量只读用例必须调用现有 `resolve_prompt_entries` / canonical prompt router。禁止为管理页面另写一套路由匹配逻辑。

### 7.2 路由优先级

沿用现有优先级：

1. 精确模型覆盖
2. 模型系列覆盖
3. 供应商覆盖
4. 能力覆盖
5. 环节通用模板
6. 代码内置提示词回退

### 7.3 模型解析上下文

地图默认加载每个环节当前系统默认模型绑定，并把最终 provider、model、capability、output contract 和 stage 传入 canonical router。用户在单个环节详情中选择其它已发布模型版本时，只预览该模型实际会命中的模板，不改变生产绑定。

现有 canonical router 不支持小说或项目级 Prompt 覆盖。首版不得提供小说、项目或整书运行级提示词切换器，避免展示不会影响真实生产的假绑定。如未来需要该能力，必须单独设计持久化 Prompt Usage Binding 和生产路由变更。

### 7.4 状态枚举

- `effective`：命中已发布模板
- `overridden`：命中精确模型、模型系列、供应商或能力覆盖
- `internal_fallback`：未命中模板，生产时会使用代码内置提示词
- `invalid_binding`：存在绑定但目标模板不可用
- `not_applicable`：该环节不使用 Prompt 路由

## 8. API 设计

新增模型中心只读接口：

```text
GET /api/v1/model-center/prompt-usage-map
```

完整地图接口不接收小说或项目参数，始终返回当前默认模型绑定下的真实结果。

单环节模型预览使用：

```text
GET /api/v1/model-center/prompt-usage-map/stages/{stage_id}/resolve?profile_version_id=...
```

该接口只读，不修改模型绑定或提示词版本。

响应核心结构：

接口一次返回完整地图，避免前端为每个环节分别请求。响应不返回密钥、供应商原始错误或未脱敏配置。

## 9. 用户操作流程

1. 用户选择生产环节。
2. 页面显示当前默认模型下的最终生效模板和解释证据。
3. “更换模板”只允许选择任务相同的已发布模板；确认后基于现有版本创建带当前模型路由条件的新草稿。
4. “编辑正文”创建不可变草稿版本，不覆盖线上版本。
5. 用户预览草稿效果。
6. 发布前显示中文影响范围，例如“当前模型的新任务将采用此版本”。
7. 发布成功后重新请求使用地图，以后端重新解析结果作为最终状态。

历史任务和既有生成证据不回写；新任务使用新发布版本。

## 10. 中文状态与错误文案

- 尚未配置模板，将使用代码内置提示词。
- 模板已发布，但当前模型条件不匹配。
- 当前模型命中了模型专用模板。
- 模板绑定无效，请重新选择已发布版本。
- 此环节不使用提示词模板。
- 发布后，所有使用默认分镜模型的新任务将采用此版本；历史任务不变。

页面不得直接展示 `exact_model_match`、`task_only_template` 等内部英文代码；代码保留在响应证据中，前端显示后端提供的中文 `source_label` 和 `message`。

## 11. 前后端边界

### 后端

- 在 `backend/app/features/model_config/` 或独立的 prompt usage application 模块中实现注册表、默认模型解析和批量路由用例。
- API 路由保持薄入口。
- canonical prompt router 仍是路由优先级的唯一所有者。
- 通过公开 facade 调用其它 feature，禁止 endpoint 间导入。

### 前端

- 在 `frontend/src/features/model-center/` 下新增 API 类型、hook 和聚焦组件。
- 默认 Prompt 页面只组装流程地图、摘要、详情和模板库入口。
- 不把解析规则、任务注册表或状态推导复制到前端。
- 单个 feature 组件控制在 200 行以内。

## 12. 性能与缓存

- 页面只发起一次地图请求和按需详情请求。
- 后端在单个数据库会话中批量加载模型绑定和已发布模板候选。
- 不在循环中逐环节执行重复数据库查询；必要时扩展 canonical router 的批量候选输入，而不是在 API 层增加 N+1 查询。
- 单环节模型预览切换时取消或忽略过期请求，避免旧结果覆盖新模型结果。

## 13. 测试与验收

### 后端契约测试

- 返回完整、稳定顺序的生产环节。
- 精确模型、模型系列、供应商、能力和通用模板优先级与 canonical router 一致。
- 未命中时返回 `internal_fallback`。
- 字幕和合成返回 `not_applicable`。
- 精确模型、模型系列、供应商和能力覆盖能反映在模板、模型和中文来源说明中。
- 不返回密钥或未脱敏供应商信息。
- 批量读取不产生逐环节 N+1 查询。

### 前端 E2E

- 默认打开提示词使用地图，而非版本表单。
- 5 秒内可从环节卡看到模板、版本、模型和状态。
- 点击环节显示真实生效详情。
- “只看问题环节”正确筛选。
- 内置回退、不适用和无效绑定显示中文说明。
- 高级设置默认折叠。
- 模板库仍可访问现有工作台。
- 发布后重新解析并更新地图状态。

### 静态验证

- 前端 TypeScript typecheck 和 build 通过。
- 后端目标测试和模型中心回归通过。
- 代码健康检查通过；遗留热点不增长。

## 14. 发布与回滚

- 先增加只读接口和新 feature 组件，再切换 Prompt 默认入口。
- 原 `PromptProfileWorkbench` 保留在模板库路由中，作为兼容路径和快速回滚面。
- 如地图解析异常，可把默认入口切回模板库，不需要回滚数据库。
- 不执行数据迁移，不改变历史模板和发布状态。

## 15. 完成标准

只有同时满足以下条件才算完成：

1. 用户可按完整生产流程查看每个环节的真实生效模板。
2. 显示结果来自 canonical router，不是前端推断。
3. 所有异常和覆盖来源使用中文直白说明。
4. 日常查看和更换模板无需接触 JSON。
5. 版本、差异、回滚和旧版兼容仍可在高级设置或模板库中使用。
6. 相关后端、前端和 E2E 验证全部通过。
