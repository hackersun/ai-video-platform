# 资产维护简化与制片对象联动设计

## Intent Lock

让资产工作台、AI 资产制片向导和资产编辑器共享同一套“可制片对象”真相，并明确区分“归档单个资产”与“停用整个制片对象”，避免误删和幽灵下拉项。

## Accepted Decision

采用方案 A：

- 归档资产只影响当前图片、音频、视频或视图文件；制片对象仍可重新生成缺失资产。
- 停用制片对象将 `StoryEntity` 生命周期置为 `archived`，同时归档该对象的全部活动资产。
- AI 资产制片向导和资产编辑器只展示后端判定为可用于资产生成的对象。
- 通用实体审核界面仍可展示候选对象，不把资产生产过滤规则复制到前端。

## UX Contract

### 资产工作台

- 保留现有三栏工作台、分页、智能集合和检查器。
- 检查器继续提供“归档资产”，文案明确其只影响当前资产。
- 对已绑定对象的资产增加“停用制片对象”入口；确认面板显示对象名称和将归档的活动资产数量。

### AI 资产制片向导

- 作为工作台内的紧凑“补齐资产”区域，不再先展示整块风格图库。
- 默认顺序：小说 → 对象类型 → 可制片对象 → 缺失视图清单 → 生成缺失视图。
- 对象选项显示活动资产数量；被停用、驳回的对象不出现。
- 风格和一致性模式收进可展开的“生成设置”。
- 已有视图和缺失视图使用同一套状态卡；失败视图保留可读错误和手工重试。

### 编辑资产

- 使用右侧抽屉，复用工作台检查器的深色面板、边框、排版和操作密度。
- 默认展示预览、名称、类型、关联范围、对象、标签、说明和资源替换。
- 小说、章节、剧本、对象字段按当前绑定范围逐步显示，不一次铺满所有层级。
- JSON、来源提示词和生成参数放在默认收起的“技术信息”中。
- 底部固定取消和保存；保存或取消后返回原工作台滚动与筛选上下文。

## Data And API Contract

- 新增资产维护领域 API，不增长现有超大 `assets.py` 和 `story_bible.py`：
  - `GET /api/v1/asset-maintenance/entity-options`
  - `POST /api/v1/asset-maintenance/entities/{entity_id}/deactivate`
- entity-options 复用 `query_story_entities_for_assets`，响应包含 `lifecycle_status` 和 `active_asset_count`。
- deactivate 在一个事务中归档实体及其活动资产，返回 `archived_asset_count`；重复停用保持幂等。
- 现有 `DELETE /api/v1/assets/{asset_id}` 保持只归档单个资产。
- 现有 `DELETE /api/v1/story-bibles/entities/{entity_id}` 暂不改变，避免破坏旧调用方；新工作台不再调用它完成停用。

## State Synchronization

- 页面加载小说上下文时，从 entity-options 获取向导和编辑器共用的对象集合。
- 停用成功后同时刷新资产和对象集合，并清除已失效的 `selectedEntityId` 与表单 `entity_id`。
- 单个资产归档后只刷新资产集合，对象选项保留。
- 切换小说或对象类型时，若当前对象不在新集合中，立即清空而不是保留幽灵选择。

## Constraints

- 不修改数据库结构，不迁移或删除 sunqy 真实数据。
- `frontend/src/app/assets/page.tsx` 当前 2245 行，改造后必须净减少。
- 新 React feature 组件不超过 200 行；新生产文件不超过 500 行。
- 后端生命周期规则只有 `story_entity_lifecycle.py` 一个所有者。
- 所有行为变化先写失败测试；最终从前端验证真实工作台。

## Acceptance Criteria

1. 归档某个资产后，其对象仍存在于向导，可重新补齐视图。
2. 停用对象后，该对象及其全部活动资产立即从工作台和选择器消失。
3. 已归档或已拒绝对象不会出现在资产向导和编辑资产对象下拉框。
4. 停用确认明确显示影响对象与资产数量，成功提示可读。
5. 编辑器为可关闭抽屉，高级技术字段默认收起，关闭后仍停留在原工作台上下文。
6. 向导默认首屏只展示核心选择、缺失视图和单一主要生成动作。
7. 桌面和移动端无横向溢出，键盘可以关闭抽屉并操作主要按钮。
