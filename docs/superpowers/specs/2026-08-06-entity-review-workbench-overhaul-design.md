# 实体审核工作台与候选质量门改造设计

## Intent Lock

把小说的“AI 资产分析”页改造成可持续处理数百条候选的实体审核工作台，并阻止模型超时后的规则碎片继续伪装成高质量 AI 结果；保留已定稿事实和历史候选，不删除真实数据。

## 已确认问题

- 《玄玉道途》当前有 646 条实体：639 条候选、2 条已定稿、5 条已拒绝。
- 当前页面只请求最新 500 条，统计、搜索、筛选和实际可见数据不一致。
- 定稿、拒绝和补全后会触发整页骨架屏，布局高度塌缩导致滚动位置回到顶部。
- 页面没有行选择，只能执行“全部安全候选定稿”，不能按用户判断批量定稿或批量拒绝。
- 后端已有更新、定向补全和重抽能力，但资产分析页没有提供直接编辑、差异预览和单条重新分析流程。
- 最近实体分析多次因模型执行超时降级为确定性规则；规则结果仍被当前质量公式打到 88 至 100 分，产生人物尾词、句子片段和无制作价值事件。

## 用户目标

用户应能在同一工作台完成五件事：快速找到候选、判断证据、修正内容、批量决策、重新分析。任何操作后都应停留在原页、原筛选和相邻记录，不需要重新滚动定位。

## 页面结构

### 顶部概览

- 保留小说标题、健康分、候选数、已定稿数、资产缺口和下一步。
- “AI 分析制作资产”显示真实执行模式。模型不可用时明确提示失败或降级，不以“AI 分析已完成”掩盖规则回退。
- 增加“重建候选库”入口，仅处理候选和已拒绝记录，已定稿及旧生产实体不参与归档。

### 筛选与批量工具条

- 服务端支持类型、审核状态、关键词、页码、每页数量和更新时间排序。
- 默认每页 50 条，可切换 20、50、100 条。
- 表头复选框选择当前页；已选 ID 跨页保留，并明确显示“已选择 N 项”。
- 批量动作包括定稿、拒绝和清空选择。定稿继续执行证据与重复风险门禁，跳过项返回可读原因。
- 搜索匹配名称、规范名、描述、别名和证据；改变筛选或搜索后回到第一页。

### 实体表格

- 表头固定，表格区域独立滚动，分页条固定在表格底部。
- 行显示名称、类型、质量、审核状态、证据摘要和最近更新时间。
- 质量分必须同时显示来源：`AI`、`规则回退`、`人工`。规则回退不得使用“AI 高质量”语义。
- 单条定稿或拒绝只更新当前行和统计，不替换整个页面。

### 右侧审核器

- 右侧面板在桌面端保持粘性，移动端改为抽屉式详情。
- 提供“查看”和“编辑”两种状态。编辑字段包括类型、名称、规范名、描述、外貌、视觉 DNA、别名和原文证据。
- 候选实体可直接保存修订；保存后仍为候选，用户再明确定稿。
- 已定稿实体修改前创建版本快照并沿用既有下游影响检查，不静默覆盖生产事实。
- “AI 重新分析”先返回差异预览，用户确认后才把结果应用到候选；模型失败不改现有实体。
- 重复项在当前实体旁展示合并建议，不要求用户滚动到页面底部寻找入口。

## 状态保持

- 首次进入页面可以显示整页骨架；后续刷新只显示局部加载态。
- 页码、每页数量、类型、状态、关键词和当前实体 ID 写入 URL 查询参数，刷新和返回页面后可恢复。
- 操作成功后优先使用接口返回值局部更新实体集合，再后台刷新统计。
- 若处理后的实体不再属于当前筛选，选择同页下一条；当前页为空时退到上一页。
- 表格滚动容器不卸载，因此定稿、拒绝、编辑和重新分析不会改变滚动位置。

## 后端契约

现有 `GET /story-bibles/entities` 列表契约保持不变，避免破坏实体库及其它调用方。新增聚焦的实体审核 feature router，不继续增长 `story_bible.py` 热点文件。

### 分页查询

`GET /api/v1/entity-review/novels/{novel_id}/entities`

查询参数：

- `page`：从 1 开始。
- `page_size`：20、50 或 100。
- `entity_type`：character、scene、prop、event。
- `review_status`：candidate、approved、rejected、legacy_active、archived。
- `query`：名称、规范名、描述、别名和证据搜索。
- `sort`：默认 `updated_desc`。

响应包含 `items`、`page`、`page_size`、`total`、`total_pages` 和当前小说的审核摘要。

### 批量审核

`POST /api/v1/entity-review/bulk-review`

- 请求包含最多 100 个 `entity_ids` 和 `action=approve|reject`。
- 复用既有证据、重复风险和生命周期服务。
- 响应逐项返回 `updated` 与 `skipped`，前端不因部分失败丢失成功结果。

### 单条重新分析

`POST /api/v1/entity-review/entities/{entity_id}/reanalyze`

- `mode=preview` 返回当前值、新值、字段差异和模型执行证据，不写实体。
- `mode=apply` 仅允许应用最近一次预览结果；候选保留 candidate 状态。
- 模型超时、配置不可用或返回不合法时返回可读错误，实体保持原样。

### 安全重建候选库

`POST /api/v1/entity-review/novels/{novel_id}/rebuild-candidates`

- 先以不落库方式运行模型并通过输出契约及严格质量门。
- 只有模型结果有效时，才在同一事务中把现有 candidate/rejected 标记为 archived，并写入新候选。
- approved 和 legacy_active 永远保留。
- 归档记录写入 `rebuild_run_id`、原因和时间，可通过既有生命周期数据追踪，不执行硬删除。
- 模型失败时整个操作不改变候选库。

## 提取质量门

- `provider_model`、`deterministic_fallback`、`supplied_candidates` 必须成为前后端可见的执行证据。
- 普通确定性规则结果不能获得 `auto_approve`；只有显式文本标签或经过模型语义验证的结果可以进入高置信区间。
- 人物名称增加尾词和语法边界检测，拦截“林辰深”“林辰正”“孙三可”等谓语粘连。
- 人物类型增加组织、家族、物品及功法边界，拦截“赵家”“朱颜果”等误分类。
- 事件必须包含可识别的主体、动作和对象或结果；时间短语、情绪状态和单个分句不能达到自动通过阈值。
- `low_production_usefulness`、证据不匹配或任一 noise 标记都禁止 `auto_approve`。
- 页面触发的 AI 分析要求真实模型结果；模型超时不会批量写入规则回退候选。

## 前端模块边界

当前路由页已超过 500 行，改造后不得增长。路由页只负责小说上下文和工作台装配，新逻辑放入：

- `frontend/src/features/entity-review/use-entity-review-workbench.ts`
- `frontend/src/features/entity-review/entity-review-toolbar.tsx`
- `frontend/src/features/entity-review/entity-review-table.tsx`
- `frontend/src/features/entity-review/entity-review-inspector.tsx`
- `frontend/src/features/entity-review/entity-edit-form.tsx`
- `frontend/src/features/entity-review/types.ts`

单个 React feature 组件不超过 200 行，业务请求继续统一通过 `api-client.ts`。

## 数据与安全边界

- 不修改或删除已定稿实体。
- 不硬删除当前 639 条候选；重建时只归档并保留审计信息。
- 不绕过定稿证据门、重复风险门或生产影响检查。
- 不自动调用可能产生费用的批量模型分析；用户明确点击并确认后才执行重建。
- 真实数据变更前先验证新结果可用，失败时保持原状态。

## 无障碍与操作细节

- 所有行选择、批量动作、分页和编辑字段都有可读标签与键盘焦点。
- 行点击不替代复选框；复选框操作不会意外切换详情。
- 状态不只依赖颜色，始终显示文字。
- 批量处理中禁用重复提交，并用 `aria-live` 或 toast 报告成功与跳过数量。
- 分页按钮提供当前页和总页数，禁用状态可被辅助技术识别。

## 验收标准

1. 639 条候选可以通过服务端分页完整访问，任意搜索结果的总数与数据库一致。
2. 用户可以跨页保留选择，并批量定稿或批量拒绝最多 100 条。
3. 单条定稿、拒绝、保存编辑后页面不回顶部，筛选、页码、选择和相邻实体保持正确。
4. 候选可直接编辑并保存；AI 重新分析提供差异预览，失败不覆盖原内容。
5. 模型超时不会显示成成功的 AI 分析，也不会新增高分规则垃圾候选。
6. “赵家、林辰深、林辰正、孙三可、朱颜果、这日中午、气血翻涌”等已知误识别样例被质量门拦截或降为拒绝噪声。
7. 重建候选库保留 2 条已定稿实体，旧候选可追溯，模型失败时数据库零变化。
8. 桌面端表头、审核器和分页可持续操作；移动端无横向页面溢出。
9. 相关后端测试、前端类型检查、生产构建和浏览器端到端用例通过。

## 验证范围

- 后端：分页排序与筛选、批量部分成功、质量门样例、重新分析预览/应用、候选重建事务回滚。
- 前端：分页、跨页选择、批量动作、编辑、重新分析差异、URL 状态恢复、操作后滚动位置。
- 真实运行：在《玄玉道途》上验证 2 条已定稿不变、旧候选归档可追溯、新候选质量和完整分页。

## 非目标

- 本次不重做通用 `/entities` 页面和资产生成页。
- 本次不改变 Production Bible 的生产可见生命周期边界。
- 本次不自动定稿新提取结果。
- 本次不新增数据库表；优先复用实体生命周期、提取运行、反馈和版本字段。
